# 已知踩坑

## 2026-11-12：同一 MCP 会话并行打开多个项目会改变写入目标

- 症状：Claude Code 验收时并行打开只读项目 A 和可写项目 B，随后提交原本用于 A 的任务标题。工具返回成功，任务文件实际落在 B，A 的目录没有变化。
- 根因：`project_open` 在桥接会话里更新唯一的 `selectedProject`；`task_create` 使用当时的选择，调用参数没有显式项目 ID。服务按实际收到的项目 B 执行权限检查。
- 教训：验收读写权限时为每个项目开独立会话，并逐个核对响应、项目目录以及允许写入项目的实际文件数量。跨项目实际工作也应串行选择并核对目标，或使用独立会话。权限分支未改动此会话选择行为。
- 参考：src/mcp/library-bridge.ts 的 `project_open` 和 `task_create`。

## 2026-11-10：开关的圆角工具类被项目样式排除

- 症状：设置里的开关 DOM 与点击测试通过，但实际页面中的轨道和滑块呈方形。
- 根因：全局 Tailwind 样式显式排除了 rounded-full，新共用开关沿用该类，构建后没有对应样式。
- 修法与教训：使用项目已有 rounded-circle 类，并以实际构建样式的页面核对开关外形。检查既有样式扫描约定后再复用工具类。
- 参考：src/web/styles/source.css、src/library-web/components/PermissionSwitch.tsx。

## 2026-11-10：新概览的详情入口回到旧界面

- 症状：项目首页只读，「完整简介」打开旧的五标签界面；窄屏首屏被进展长文占满。
- 根因：给详情保留旧地址时同时保留了整套旧布局，编辑也留在旧组件里。之前的浏览器验收检查了能否跳转和读写，但没有从用户的入口核对同页阅读、编辑和首屏层级。
- 修法与教训：旧地址指向同一概览的对应栏目。从概览点击简介、就地编辑并重读已保存正文；使用真实长文核对手机和桌面先看到什么。
- 参考：ProjectHomePage、OverviewFieldEditor、library-web-overview.test.tsx。

## 2026-11-05：分页后重复套用同名大标题

- 症状：选中“功能与用法”后，下面又显示同名大标题，四页均如此，额外占一行操作区与留白。
- 根因：新增页签导航后仍复用通用PageHeader，两处显示同一个page.label，没有分配标题职责。
- 修法与教训：概览导航与操作合并，选中页签提供可见页面名称，正文从实质内容开始；保留读屏h1。组合页头与导航时核对信息是否重复，不能只检查路由和保存成功。
- 参考：OverviewPage、library-web-overview.test.tsx的重复标题回归用例。

## 2026-11-05：正文标记校验与解析的空白规则不一致

- 症状：带缩进或尾部空白的保留节标记可能绕过输入校验，解析时却被识别为节边界，导致正文被截断。
- 根因：输入正则只匹配无缩进的整行，解析器先trim再匹配。新增项目约定的回归用例暴露了这条规则差异。
- 修法与教训：概览和目标更新统一使用与解析器相同的去首尾空白整行判定；以真实HTTP拒绝结果及原文件不变作为回归断言。
- 参考：src/library/overview.ts的hasOverviewSectionMarker，library-agreements.test.ts。

## 2026-11-05：日期字段在时区与编辑默认值之间被误解释

- 症状：UTC仍是前一天时，本地今天会被误判为未来；修正归档时，未知日期或调整日期可能被表单默认的今天替代。
- 根因：用UTC字符串截取日期判断本地日；编辑表单只读取completedAt，未区分adjustedAt和明确未知，也没有保留原时间粒度。
- 修法与教训：仅日期按本地日校验；完成时间、调整时间、记录时间分别处理，null明确未知。只改说明时保留原日期与粒度。发布前以Asia/Shanghai午夜和真实页面的归档日期修正测试覆盖。
- 参考：library-dynamic.test.ts、library-web-overview.test.tsx。

## 2026-11-05：固定浅色页面内出现深色正文块

- 症状：架构页的图与正文段落变成黑底，页面标题和职责名称仍是浅色页面样式。
- 根因：项目空间固定浅色，但共用正文组件没有声明主题，第三方 Markdown 样式根据系统 `prefers-color-scheme: dark` 自动采用深色变量。上一轮只检查了排布和正文唯一性，没有加载主题 CSS 检查深色偏好，程序化检查遗漏了该显示问题。
- 修法与教训：在项目空间和正文组件明确浅色模式，正文外层和预览层背景透明、文字继承页面；不改动另一个支持深色主题的旧看板。回归检查加载实际安装的第三方 CSS，逐个检查浅色和深色偏好下每层正文的主题与背景。
- 参考：`src/test/library-markdown-theme.test.tsx`、`src/library-web/components/Markdown.tsx`。

## 2026-11-05：组成表与交互列表重复显示

- 症状：架构页既显示完整组成表，又在主要流程之后出现一组没有标题的折叠条目；职责必须逐个点开。
- 根因：完整 Markdown 与从同一表格派生的交互组件分别渲染。解析器测试只证明能提取行，没有断言实际页面中同一职责出现几次、是否默认可读。架构正文还混入了本轮测试过程。
- 修法与教训：在源表位置替换呈现，阅读与编辑预览使用同一组件；挂载真实页面断言唯一性、可见性及相对顺序。把工作验证写回进展或任务。
- 参考：`src/test/library-web-architecture.test.tsx`、`plan/V1.1/ARCHITECTURE-READING-FIX.md`。
