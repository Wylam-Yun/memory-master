# 在聊天中建立项目与选择已有项目

从源码首次启动时，在仓库运行 `bun install` 和 `bun src/cli.ts serve`，打开终端打印的网页地址，选择记忆库保存位置，再到「全局设置」启用 Agent 客户端，并打开「默认允许修改」以允许它创建项目。重连 MCP 或开启新聊天后，可以说“在 Memory Master 建立一个叫订单系统的项目，关联 `/Users/我的用户名/workspace/orders`，记录刚才确认的需求”。

Agent 会先查询相关项目。候选摘要包含名称、简介、当前进展和可选的本地目录。发现潜在相似内容后，它会在当前聊天说明原因，询问更新已有项目还是新建项目。用户选择已有项目后，它先读取最新内容，再保存已确认的补充。用户要求新建时，创建成功即选中项目，继续整理背景、决定、进展和任务。

搜索按名称和概览正文做文本匹配，也支持查找相同的关联目录；Agent 结合聊天上下文判断语义相关性。可以换几个关键词搜索，或查看项目列表后打开候选核对。需要持续记录的新工作可以先在聊天决定项目归属。查询结果本身不会修改项目正文。

网页新建项目时可展开「关联本地文件夹（可选）」填写已有的绝对目录。项目已经建立时，打开概览，在项目名称下点击「关联本地文件夹」或「修改关联」。填写完整路径保存，清空后保存可解除关联。Agent 也可按用户提供的路径进行同样操作。关联目录用于定位工作文件，进展和任务保存在记忆库。修改时如果他人已经更新，会显示最新路径并保留你的输入，点击「重新读取关联」加载当前设置，核对后再保存。

项目列表每隔五秒及切回网页时刷新，因此聊天创建的项目会出现在已打开的网页中。升级后重启服务，在「全局设置」重新启用客户端以安装新版 Skill 和指令，再重新连接 MCP，新增工具才会出现在客户端。

# 删除与恢复项目

「所有项目」的每个项目右侧，以及项目概览标题旁，都提供「删除项目」。点击后核对项目名称和影响范围，选择「取消」保留项目，选择「确认删除」将项目从列表中移除。

项目的概览、任务、架构、资料和变更记录会一起移入记忆库的 `.trash/<项目ID-随机字符>/<原文件夹名>`，关联的本地工作文件夹保留。打开确认框后，如果其他人或 Agent 更新了项目，会提示重新核对，取消后再次点击删除可读取最新状态。

需要恢复时，在文件管理器显示隐藏文件夹，进入记忆库的 `.trash`，将对应项目的完整文件夹移回记忆库顶层，刷新网页。恢复时保留完整的 `memaster` 和「资料」目录，选择空闲的文件夹名以保留已有内容。恢复后沿用原项目 ID，可继续编辑。

# 管理项目资料

进入项目的「资料」页，点击「上传资料」选择文件，单份最多 10MB。点击文件名可以阅读文本或 Markdown，其他格式可从详情页下载原件。

资料列表每一行右侧提供「删除」，详情页的「下载原件」旁也有删除入口。点击后核对弹窗中的文件名，选择「确认删除」移除记忆库中的上传文件，选择「取消」关闭弹窗。列表删除成功后刷新文件清单，详情页删除成功后返回资料列表，变更记录会显示此次删除。

同名资料在你阅读后被替换时，删除会提示版本冲突。取消删除并刷新页面，核对最新文件后再操作。需要再次使用已删除的资料时，可重新上传。

# 阅读和维护项目架构

进入一个项目后，选择「项目架构」。先读项目整体说明和关系图，再向下阅读「各部分做什么」与主要流程。每个部分的名称和职责直接展示，不用先点击才能读到。

项目空间统一使用浅色展示。即使电脑设置为深色模式，正文与架构内容也沿用页面底色，不需要另找主题开关。

点击图中的一个节点，页面会定位并短暂突出对应说明。即使不操作图，也可以从上到下阅读全部职责。需要看来源或关联任务时，展开该部分的「补充信息」；其中只显示当前重点 P0 任务，点击任务名称进入任务页。

例如，读书会项目可以有「报名安排」「场地准备」「阅读材料」「现场交流」四部分。图说明报名人数怎样影响场地安排，下面的文字解释每部分做什么，最后的流程说明先后顺序。

选择「编辑」可以修改架构 Markdown，下方预览与保存后的排布一致。组成表仍在编辑内容中，网页将它显示成说明列表，不会再重复展示一份表格。没有组成表的旧文档保持原来的正文展示。没有整理架构时，可以在 Agent 聊天中说：「打开我的读书会项目，根据已有说明整理项目架构。」

架构只记录项目组成与关系。测试是否完成、另一位 Agent 是否接手和下一项发布工作，应在概览的当前进展或任务中查看。Agent 会按安装的内容标准维护；功能开关和授权仍在设置页管理。


# 管理目标与动态进展

打开项目先看「概览」。项目名下方是简介首句，点「完整简介」在原处展开全文。最新进展先显示当前停点和下一步；有明确需要你决定的事也会直接显示。「未完成或未验证」可按需展开。点击「编辑进展」可在原处修改这份简报。点击任务名定位对应任务，或点「查看全部任务」进入管理页并查看已完成任务。

## 目标

在概览的「当前目标」选择「管理目标」→「添加目标」，用一句话填写希望达成的结果。需要你认可效果后才能算完成时，勾选“完成前需要我确认”。Agent会先在聊天中询问，得到确认后再归档。

目标达成时选择“完成”，核对实际完成日期后保存。目标移到默认折叠的“已完成目标”，展开可以看到原文与日期。需要回顾时再展开，历史多时点“显示更多”。日期记错或无法确认时，选择“修正日期”；不确定的历史日期可以明确标为未知。

方向变化时选择“调整”。填写新目标会保留原目标为“已调整”，同时建立新的目标；留空表示不再推进。旧目标不会冒充已完成。旧版长文本作为“原有目标”保留，不会自动猜出哪些已经做完，可以在聊天中让Agent逐条整理确认过的目标。

## 阶段进展

关键成果实际完成后，选择“记录阶段成果”，填写标题与比标题更详细的成果说明。比如：“首次读书会完成；参与者已完成主题讨论，并收到整理后的阅读材料。”日常改字、配置和每次聊天不各建一份阶段报告。

记录保存在当前进展下方的“阶段进展”，默认折叠、按完成时间最新在前。展开后先看到成果标题和完成日期，点击某条成果才显示完整说明及“修正记录”，补充或纠正同一成果，不用重复创建。完成目标时也可勾选“同时记录一项关键阶段成果”，让目标归档与成果一起保存。

完成日期默认是今天；补录过去成果时填写实际日期，不知道就勾选“日期不确定”。系统另外记录保存时间，保存时间不等于成果完成时间。

## 通过Agent维护

在原来的Codex或Claude Code聊天中指定项目，例如：“打开读书会项目。材料已经发给所有参与者，更新最新进展；把让参与者提前拿到材料的目标归档，并记录这项阶段成果。”Agent先读取项目，再使用目标及进展工具保存。目标和阶段成果共用概览版本，其他人已经修改时会提示冲突。网页也会保留输入，展示最新内容，核对后再明确选择保存。

已经开启的Agent会话可能仍缓存旧工具清单。更新本机Skill后，重新连接Memory Master的MCP或开启新会话，才能使用新增的目标与阶段进展工具。


# 项目约定与换Agent接手

项目约定记录以后仍要遵守的安排。例如，需要用户决定时直接在聊天里问。当前进展记录现在做到哪，更新进展不会覆盖这些长期安排。

在概览展开「项目约定」，选择「打开项目约定」，再点击「编辑」。用自然语言填写已确定的决定和限制后保存，修改前后可在变更记录中查到。也可以在聊天里说：「打开 memmaster，记录需要用户决定时直接在聊天中询问。」

只记录已经确定的内容。用户否决的方向和技术尝试失败要分开；不确定的建议先在聊天讨论。普通改动不需要补理由，只有会影响后续工作的关键决定才保留必要背景。既有方案或资料用入口引用，不再抄一份全文。

换一个 Agent 后，它先读最新进展、当前目标和相关任务，再按需查完整背景、项目约定、关键路径与历史。例如：「已经核对目标归档确实保存。下一步接手一项真实待办，确认任务更新出现在网页上。」已回答的问题和仍有效的决定可以沿用。

本版吸收Jiaojie和Matt handoff的内容规则，沿用共享项目读取；不会自动创建ZIP交接包、启动后台Claude或增加交接中心。来源与许可随Skill一起分发。

# 一致的内容名称

人和 Agent 共用同一份项目记录。展开「完整简介」「项目约定」或「关键路径」后，可以直接在对应栏目阅读和编辑。「编辑用法」也在概览里。保存只更新该栏正文，折叠或离开后仍保留未保存的草稿。旧的详情链接仍能打开同一概览的对应栏目。

「历次进展」打开筛选过的变更记录。展开「历史目标」查看原有、已完成和已调整的目标。最近完成和阶段成果默认收起；展开「阶段成果」后可记录或修正成果。较长且没有小标题的旧进展先显示开头，展开「完整进展」可读原文。

「功能与用法」先显示最新功能及用途，步骤和较早功能按需展开。「完整功能与用法」可读原文，有至少三个主要章节时可用目录定位。

开发项目可展开「关键路径」→「编辑关键路径」。例如记录「概览交互测试 · 核对导航 · 工作区 src/test/library-web-overview.test.tsx」。服务器条目同时注明服务器名和服务器内路径。保存后可让 Agent 读取同一个项目的 `criticalPaths` 核对。

人和Agent读取同一份Markdown。要整理进展，可以在聊天中说：“打开memmaster，用已完成、当前停点、未完成或未验证、下一步整理当前进展，有内容才写。”没有新增四个保存字段，也不需要另写交接摘要。


# 管理 Agent 访问权限

从「所有项目」右上角打开「全局设置」。找到要接入的 Agent，打开「允许连接」。客户端成功接入后，就能读取对它开放的项目。关闭「允许连接」会切断这个 Agent 对所有项目的访问。新的 Agent 接入后默认只读；已启用的旧客户端升级后保留原有修改能力，你可以随时关闭「默认允许修改」。

如果只想让 Codex 修改「读书会」这一个项目：

1. 在全局设置允许 Codex 连接，保持「默认允许修改」关闭。
2. 打开「读书会」，从左侧栏底部进入「项目设置」；窄屏时从顶栏的「项目导航」进入。
3. 在 Codex 一行打开「允许修改」。该项目会显示「可以读取和修改」，仍继承全局的其他项目保持「只读」。可以在 Codex 聊天里分别尝试更新两个项目的进展，只有「读书会」会保存成功。
4. 如果连读取也要停止，在项目设置关闭「允许连接」。该项目不再出现在 Codex 的项目列表里，之前打开过的会话也不能继续访问。
5. 点击该 Agent 的「恢复继承」，清除它在这个项目里的例外。以后全局默认值变动时，该项目也随之变化。

相似项目搜索只返回对该 Agent 开放的项目，只读时也可使用。聊天中新建项目需要开启「默认允许修改」；更改已有项目的关联目录需要该项目的修改权限。

这些设置限制的是 Agent 通过 Memory Master 工具的访问。你仍可以在网页编辑项目。设置不会改变本机操作系统的文件权限。


### 同一会话处理多个项目

可以在同一个 Codex 或 Claude Code 会话中交代多个项目的工作。Agent 先用 `project_open` 获取各项目的 ID，再把对应 ID 作为每次读取或修改的 `project_id`。例如，读取项目 A 的概览后，只把 A 的 ID 和刚读取的版本一起提交给概览更新工具。随后打开项目 B，也不会把针对 A 的调用改送到 B。

项目内容调用（包括 `project_update` 关联目录）缺少 `project_id` 时会返回 `PROJECT_ID_REQUIRED`。更新并重启 Memory Master 后，在「全局设置」重新启用相关客户端以刷新安装的指令和 Skill，再开启新的 Agent 会话以加载新版工具定义。自行编写的 MCP 调用需要增加这个必填参数。
