# Memory Master 逐页信息架构与线框图

状态：2026-11-05 独立设计提案，待审阅。本版任务只保留名称、状态和按需展开的已有说明，不设置待决定板块、验收项和负责人。资料点击查看、架构图等尚未全部实现。功能来源和依赖见 [研究报告](UIUX-RESEARCH.md)，尺寸与组件规则见 [设计规范](DESIGN-SYSTEM.md)。

线框图使用 Memory Master 自身的前端研究内容作演示，不引用其他本地项目。所有示例状态只用于说明排布，不冒充真实项目进度。

## 1. 导航地图与用户流程

```text
首次访问 → 安全进入 → 选择记忆库 → 所有项目
                                     ├─ 新建项目（短表单）
                                     ├─ 设置
                                     │   ├─ Agent连接与授权
                                     │   └─ 保存位置
                                     └─ 打开一个项目
                                         ├─ 概览（默认）
                                         │   ├─ 编辑正文
                                         │   └─ 项目信息（可选关联文件夹）
                                         ├─ 任务（P0）→ 按需展开说明
                                         ├─ 项目资料 → 查看原件/下载
                                         ├─ 项目架构 → 节点说明
                                         └─ 变更记录 → 前后变化
```

任务是当前要推进的工作，变更记录是已发生的修改。需要用户拍板时，Agent在当前聊天中询问，网页不设问题板块。人和Agent对同一对象的修改出现在同一份记录中，不按操作者分成两套项目。

从任何项目页到其他项目页为一次导航。资料和历史详情都有明确返回位置和可直接打开的地址，任务说明在列表内按需展开；浏览器后退返回原列表位置。切换项目只改变当前网页作用域，不自动切换其他Agent会话所选项目。

## 2. 项目内通用框架

```text
┌──────────────────┬─────────────────────────────────────────────────┐
│ Memory Master    │ 页面标题                          当前页主操作 │
│                  │                                                 │
│ [当前项目    ▾]  │                                                 │
│                  │              当前页面核心内容                   │
│ 概览             │                                                 │
│ 任务             │                                                 │
│ 项目资料         │                                                 │
│                  │                                                 │
│ 项目架构         │                                                 │
│ 变更记录         │                                                 │
│                  │                                                 │
│ 所有项目         │                                                 │
│ 设置             │                                                 │
└──────────────────┴─────────────────────────────────────────────────┘
```

- 左栏224px；不用第二条常驻项目列表。项目切换器列出现有项目，底部提供「所有项目」，不加载无依据的跨项目统计。
- 主区只有一个页面标题和当前页操作。全局配置留在设置；切项目、导航、正文编辑互不混在同一工具栏。
- 任务和资料先用列表；任务名称加状态，说明按需展开。点文件名在网页看资料，不新增资料入口。无选择时不留空白右栏。
- 项目内仅五个入口，不出现待决定板块、任务内问题标签或未回答角标。需要拍板时继续在Agent聊天中协作。
- 项目架构与变更记录用空间间隔和日常入口区分，不再添加一行灰色说明文字。项目架构尚未交付时不放可点击的空壳功能；交付后允许项目内容为空。

## 3. 首次使用与服务恢复

### 3.1 页面目的及第一眼

让用户知道「项目记忆保存在本机哪里」，完成一次明确设置。它不是产品宣传页，不展示功能卡片或复杂步骤条。

```text
┌──────────────────────────────────────────────────────────────────┐
│ Memory Master                                                    │
│                                                                  │
│                 选择项目记忆的保存位置                           │
│                                                                  │
│                 [默认目录，完整可读________________]             │
│                 [使用此位置]   更改位置                          │
│                                                                  │
│                 一个位置保存各项目的独立记录。                   │
└──────────────────────────────────────────────────────────────────┘
```

| 区块 | 具体内容与动作 | 优先级与理由 |
| --- | --- | --- |
| 顶部 | 品牌名，不提供未配置前无法使用的项目导航 | 次要，建立产品身份即可 |
| 中部标题 | 选择项目记忆的保存位置 | 最高，明确本次操作 |
| 位置字段 | 已有默认目录，允许粘贴修改；显示完整值 | 最高，不迫使用户从空白路径开始 |
| 主操作 | 使用此位置；提交时显示保存中，成功进入项目列表 | 最高，只有一条完成路径 |
| 辅助说明 | 一句解释存储关系，非必填字段教程 | 次要，避免把目录误当代码工程 |
| 错误 | 位置无效或不可写时靠近字段；保留输入 | 必须，不把失败写成空项目列表 |

网页普通file输入无法直接替代服务端绝对目录选择。本阶段先做好默认位置和手动修改；原生文件夹选择由后续桌面容器提供，不能在纯Web方案中假设已经具备。

访问密钥在当前网页版仍是授权边界：有可信带密钥入口时直接进入；缺少或失效时保留独立恢复屏，允许粘贴完整访问地址。只在该屏解释「从启动窗口重新打开」。未来桌面容器可提供可信入口，但本轮不删除授权。

服务断开时显示当前页及「Memory Master 服务已停止，重新打开应用后重试」，操作暂停、草稿保留。浏览器关闭不等于服务关闭，不提供误导文案。

第一眼看到项目名称和「新建项目」，常用动作是进入已有项目。无需先看路径、UUID或所有客户端的连接信息。

```text
│ Memory Master                                            设置   │
│                                                                  │

│                                                                  │

│ Memory Master                                            →       │

新建项目
┌──────────────────────────────────────┐
│ 新建项目                         关闭│
│ 项目名称                             │

│                     取消  [创建项目] │
└──────────────────────────────────────┘
```

| 区块 | 内容与交互 | 优先级与理由 |
| --- | --- | --- |
| 顶部 | 品牌、设置 | 低频配置不占项目行 |
| 页头 | 所有项目＋新建项目 | 唯一主操作 |
| 核心列表 | 名称整行可进入；行高至少64px；长名允许两行 | 名称是当前可靠且稳定的辨认信息 |
| 可选过滤 | 超过约12个项目时出现「查找项目」名称过滤 | 只对当前项目列表过滤，不增加复杂检索 |
| 二级信息 | 已有关联目录放项目信息详情；未有简介聚合接口前不展示虚构摘要或更新时间 | 不为做满卡片新增无依据的统计 |
| 空状态 | 还没有项目＋新建项目 | 不同时出现空列表框与常驻新建表单 |

项目名重复、关联目录无效时在表单内反馈，保留已输入名称。创建成功直达新项目概览，提供填写入口，用户可直接转去Agent聊天补充内容。无需先选择开发、学习等类型。

后续若确有大量项目，可增加从已有概览读取的一句简介；应作为数据接入项评估，不从文件夹名生成。

第一眼看到项目简介和当前进展，主要操作是阅读；修改通过右上角「编辑」。阅读顺序与主SPEC统一为简介、当前进展、目标、功能与用法。

```text
┌──────────────┬───────────────────────────────────────────────────┐
│ 项目导航     │ 概览                                      编辑    │
│              │                                                   │
│              │ 项目简介                                          │
│              │ Memory Master 让人和多个Agent共享项目管理进度。   │
│              │                                                   │
│              │ 当前进展                                          │
│              │ 已完成：……                                        │
│              │ 正在推进：……                                      │
│              │ 阻塞与下一步：……                                  │
│              │                                                   │
│              │ 项目目标                                          │
│              │ 1. ……                                             │
│              │ 2. ……                                             │
│              │                                                   │
│              │ 功能与用法                                        │
│              │ 创建项目                                          │
│              │ 在项目列表选择「新建项目」，输入名称。             │
│              │ ……                                                │
│              │                                                   │
│              │ 查看项目架构 →                                    │
└──────────────┴───────────────────────────────────────────────────┘
```

| 区块 | 展示内容 | 交互 | 位置理由 |
| --- | --- | --- | --- |
| 页头 | 概览、编辑；项目信息通过二级菜单进入 | 编辑进入同页表单 | 阅读默认，不把保存按钮作为页面常驻主角 |
| 简介 | 是什么、服务谁、解决什么；完整正文 | 阅读，链接按需进入资料 | 先建立项目上下文 |
| 当前进展 | 维护的一份最新摘要，允许多段正文 | 显式编辑，刷新可看到Agent更新 | 直接回答到哪了，不要求去历史中拼接 |
| 目标 | 要做成的效果及可观察结果 | 阅读与编辑 | 保留长期方向，不和任务完成率混用 |
| 功能与用法 | 当前已有能力或交付内容＋对应使用方法 | 文件或操作入口有真实来源才链接 | 普通项目可以说明现有报告、清单等使用方式 |
| 结构入口 | 一条文字链接 | 进入结构页 | 保留了解关系的路径，不嵌入难读缩略图 |

正文建议760–820px最大宽；四段内容自然向下流动，无背景卡片、内部滚动和常驻右栏。不展示自动计算的百分比、Agent头像列、任务缩略列表、资料缩略列表或历史预览。

编辑态沿用四块标题与顺序，每块编辑区按内容增高。顶端提供保存、取消和未保存状态；长页可用底部固定在内容容器内的操作条，注意不遮正文。切页后保留项目内草稿，取消才恢复保存值。编辑中收到新版本时展示比较入口，不能清空草稿。`features`接通前不能让新字段保存成假成功。

空字段只显示「未填写」与编辑动作，示例文字只在用户主动填写时提供。Agent不得为使页面好看虚构已完成功能。

## 6. 任务：名称与完成状态

第一眼看到当前P0任务。常用操作就是添加任务、看状态和直接勾选整条任务完成，不需要理解验收项或管理负责人。

```text
┌──────────────┬───────────────────────────────────────────────────┐
│ 项目导航     │ 任务                              [＋ 添加任务]   │
│              │ P0 · 当前重点                                    │
│              │                                                   │
│              │ ☐ 梳理前端页面内容                      进行中    │
│              │ ☐ 补齐网页中的资料查看                  待开始    │
│              │                                                   │
│              │ 已完成（3）                              展开     │
│              │ ☑ 核对现有页面入口                       已完成   │
└──────────────┴───────────────────────────────────────────────────┘
```

| 区块 | 内容与操作 | 位置理由 |
| --- | --- | --- |
| 页头 | 任务、添加任务 | 一个明确主操作；新建只需名称 |
| 任务列表 | 勾选框、名称、状态 | 用户一眼读懂并直接操作，不增加表格字段 |
| 任务说明 | 已有描述可点开名称后在该行下展开，空描述不占位置 | 保留必要背景，默认界面仍简单；不新增常驻详情栏 |
| 已完成 | 默认折叠，可展开查看或改回未完成状态 | 当前工作优先，已完成记录仍能复查 |

勾选直接更新整条任务为已完成，无需先填清单或确认负责人。尚未完成时保持待开始或进行中；需要修改状态时用明确文字选项，实际合法状态遵循项目配置。操作失败恢复到已保存状态并提供重试。

网页只展示P0，不提供全部优先级切换。P1由Agent维护。任务名称与状态的更新继续使用版本检查和自动变更记录，旧数据中额外字段原样保留，但不在本版接入为新任务表单。

需要用户决定时在当前Codex或Claude Code聊天中询问，不在任务内增加问题标签或待回答提示。

## 7. 项目资料：人和Agent查阅同一份原件

第一眼看到文件名及「上传资料」。上传后直接点文件名在网页查看内容，不需要额外找入口或设置权限；上传是用户明确选择，不扫描用户磁盘。

```text
┌──────────────┬───────────────────────────────────────────────────┐
│ 项目导航     │ 项目资料                            [上传资料]    │
│              │                                                   │
│              │ 文件                              大小    更新    │
│              │ 前端需求说明.md                   8 KB    今天  → │
│              │ 页面研究记录.txt                  4 KB    昨天  → │
│              │ ……                                                │
└──────────────┴───────────────────────────────────────────────────┘

资料阅读
┌──────────────────────────────────────────────────────────────────┐
│ ← 返回项目资料    前端需求说明.md                       下载原件 │
│                                                                  │
│                    原始文档内容                                  │
│                    标题、正文、列表……                            │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

| 区块 | 内容与交互 | 优先级与理由 |
| --- | --- | --- |
| 页头 | 项目资料＋上传；附近只保留「每份最多10MB」这一有用限制 | 用户需要知道可执行动作与真实限制 |
| 文件列表 | 名称、大小、更新时间；整行进入查看 | 文件名正常字体，去掉默认小号等宽阅读负担 |
| 上传反馈 | 当前文件、上传中/失败/已完成；不使用虚构百分比 | 当前fetch流程无真实进度数据，先用明确阶段 |
| 名称冲突 | 识别已有同名，明确替换或取消；失败保留待上传文件 | 服务端已有同名覆盖，不能静默吞掉原件 |
| 查看 | 先支持文本/Markdown原件，安全渲染；无预览格式显示文件信息＋下载 | 不把下载当预览，不承诺PDF/Office解析 |
| 大文件内容 | 限制预览字节，说明只显示部分并提供完整下载 | 防止浏览器冻结，普通短文不内滚动 |

必须补web授权的单文件读取/下载API。Agent读取现有能力不能直接用于网页，否则会混淆撤权边界。资源名按URL编码，返回类型与下载文件名安全处理，HTML等可执行格式以文本或下载呈现。

不新增文件夹、自动标签、全文搜索、OCR、资料版本和删除入口。少量资料直接列表；数量增加后可加当前文件名过滤，按真实使用再决定。

## 8. 项目架构：总图、职责说明与主要流程

先读一小段整体说明和总图，再阅读各部分职责，最后看主要流程。职责默认直接可读，点击图节点只是辅助定位；来源、关联任务等补充信息按需展开。组成表在原位置显示为说明列表，不同时渲染原表格和追加列表。

```text

│ 项目导航     │ 项目架构                           编辑    放大   │
│              │                                                   │
│              │              项目共同记忆                         │
│              │                 ↓                                 │
│              │       网页管理 ←→ 项目记录 ←→ Agent协作           │
│              │                                                   │
│              │                                                   │
│              │ 各部分做什么                                      │
│              │ 网页项目空间                                      │
│              │ 供人阅读项目说明、任务、架构、资料及变更。         │
│              │                                                   │
│              │ 项目记录                                          │
│              │ 保存概览、任务和架构，供双方共同维护。             │
│              │ ▸ 补充信息                                        │
│              │                                                   │
│              │ 主要流程                                          │

```

| 区块 | 内容与交互 | 优先级与理由 |
| --- | --- | --- |
| 页头 | 项目架构；实际可用的编辑、放大 | 不在日常页面展示Mermaid专业词 |
| 图 | 主要组成与关系，完整标签，当前事实与计划有文字区分 | 人先理解整体，不依赖悬停 |
| 各部分做什么 | 名称与完整职责默认可读；点图节点滚动定位并短暂突出对应说明 | 不依赖逐个点击，默认上下排布保证阅读宽度 |
| 补充信息 | 实际来源、P0关联任务，使用文字明确的折叠入口 | 有内容才显示，不强制代码位置或证据链接 |
| 主要流程 | 放在职责说明之后，用段落或步骤解释各部分怎样衔接 | 不重复职责，不混入本轮测试和发布待办 |
| 复杂内容 | 节点细图或放大画布；始终有返回总图 | 复杂度逐步披露，不能缩字塞下所有节点 |

架构读写已接入。功能交付后的空状态显示「尚未整理项目架构」，用户可在Agent聊天中请求整理，不要求绑定本地目录。结构编辑可先提供有标签的图源编辑与预览；面向普通用户的一键可视化拖拽编辑器不是本轮默认范围。不要新增无法实现的「自动生成」按钮来伪装产品内具备LLM执行能力。

窄屏以总图＋文字说明上下排，画布允许局部二维移动；正文说明保持正常流。节点键盘可选，单纯看图困难时仍可阅读完整组成说明。

## 10. 设置：配置结果清楚，专业细节按需

第一眼看到Codex和Claude Code是否允许访问、配置是否成功。常用动作是启用或停用一个客户端。记忆库位置放在下一节。

```text
┌──────────────────────────────────────────────────────────────────┐
│ ← 所有项目                              设置                     │
│                                                                  │
│ Agent连接                                                        │
│ Codex          允许访问 · 已接入                         [开关]   │
│ Claude Code    已配置，等待接入                           [开关]   │
│                打开客户端新会话后接入。                          │
│                                                                  │
│ 保存位置                                                         │
│ [当前记忆库完整路径________________________________________]     │
│                                                      更改位置    │
│                                                                  │
│ 技术详情                                                展开     │
└──────────────────────────────────────────────────────────────────┘
```

| 区块 | 内容与交互 | 优先级与理由 |
| --- | --- | --- |
| 连接行 | 客户端名、授权开关、配置/接入状态 | 当前开关授权整个记忆库，不能画成单个项目权限 |
| 配置过程 | 配置中、配置失败＋重试、等待新会话接入 | 「启用」不等于「已连接」，不能提前显示成功终态 |
| 权限说明 | 启用将自动配置并允许该客户端读写记忆库；关闭后服务拒绝读写 | 是会改变用户预期的必要说明，不用小号灰字藏起来 |
| 最近接入 | 详情展开后显示已有lastSeenAt | 它不是心跳或任务执行状态，不写「在线工作中」 |
| 保存位置 | 可读完整路径，修改时明确是切换库，不自动搬迁文件 | 防止把切换位置误认为迁移全部数据 |
| 技术详情 | 安装位置、原始错误、必要诊断；凭据默认隐藏 | 普通用户先看结果，开发者仍能排查；不为视觉清爽删除诊断能力 |

切换保存位置前展示将切换查看的库，原目录文件保留；首次选择空位置时给出预期，不做后台迁移。配置失败只影响该客户端行，另一客户端与项目阅读保持可用。

网页检查状态可手动刷新，并在可见时低频重读；没有真实心跳能力前不显示不断闪动的在线圆点。不要加入模型选择、token用量、会话聊天、团队成员或权限角色管理。

## 11. 各页面共同的状态与扩展位置

| 状态 | 页面中的表现 |
| --- | --- |
| 初次加载 | 保留页面标题与导航，核心区域占位；不每个字段单独转圈 |
| 空内容 | 一句真实状态＋一个合适动作；空结构不阻断任务 |
| 写入中 | 正在操作的按钮与字段反馈；禁止重复提交，其他阅读不整体清空 |
| 成功 | 对应区域显示已保存/任务已完成/上传完成；不弹大型成功对话框 |
| 写入失败 | 就地错误、保留输入、重试；不把空列表当失败 |
| 外部更新 | 阅读态重读；编辑态提示有新版本，保留双方内容供比较 |
| 服务断开 | 全局一条连接提示，暂停写入，保留草稿，提供重试 |
| 权限失效 | 网页入口密钥失效走恢复屏；Agent撤权显示在设置，两个概念不混用 |
| 不存在对象 | 显示明确缺失与返回当前项目列表的入口，不改选其他项目 |

未来新功能先问它服务哪个用户目的：是任务列表、资料阅读、项目关系还是应用配置。能够附着现有内容时放二级，不为每个数据表新增一级菜单。只有独立且高频的新任务经用户确认后才扩一级。该规则为导航扩展位置，不预建插件市场、自定义对象或多套项目模式。
