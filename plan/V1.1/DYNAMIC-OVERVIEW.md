# 动态概览：目标归档与精准进展

状态：产品规则已获用户认可，配套实现与验收见 [DYNAMIC-IMPLEMENTATION.md](DYNAMIC-IMPLEMENTATION.md)。

本方案补充并覆盖 V1.1 中将目标、进展仅作为整段正文维护的规划。项目仍保留概览、任务、项目架构、资料、变更记录五页，不新增归档菜单。产品实现、网页展示、Agent 工具和 Skill 必须配套，不能仅靠 Skill 手写归档文本。

## 已确认的维护规则

| 内容 | 写什么 | 怎样维护 |
| --- | --- | --- |
| 简介 | 为谁做、解决什么问题、主要怎样使用 | 定位或用途变化时修订，不按时间机械重写 |
| 当前目标 | 每条用一句完整的话表达希望达成的结果 | 根据用户确认的方向维护，具体执行工作放在任务里 |
| 当前进展 | 比目标详细、精准的最新简报，说明已有结果、当前工作、剩余范围和下一步 | 整理并替换过时摘要，不在末尾连续追加聊天或每日流水 |
| 阶段进展 | 已完成关键成果的标题、完成日期和成果说明 | 只有关键成果实际完成才新增；不按聊天次数、工作轮次或每次保存生成 |
| 历史目标 | 原目标、完成或调整状态及相应日期 | 保留历史供展开查看，不覆盖或删除旧目标来掩盖方向变化 |
| 功能与用法 | 当前确实可用的功能或交付内容，以及入口、步骤和结果 | 新能力确认可用后补充；步骤、限制或入口变化时同步修正 |
| 项目架构 | 当前组成、职责、关系和主要流程 | 组成关系变化时维护，不混入进展流水与任务列表 |

## 当前进展的精度

“简报”指整理后的最新情况，不等于一句话、固定短字数或删掉关键背景。进展应当比目标更详细，但详细程度来自准确描述结果和边界，不来自堆砌实现代码、工具调用、测试日志和聊天记录。

进展需要让首次接手者知道：

- 哪一部分已有实际结果，结果具体是什么。
- 哪一部分正在推进，目前到哪一步。
- 还有哪些工作未完成、哪些效果尚未验证；有影响推进的阻碍时再写阻碍。
- 下一步具体推进什么。

以上是内容检查角度，不要求页面和正文机械分成四个必填字段。按实际情况用自然段或简短列表表达。不要使用无依据的完成百分比，不把“已写代码”“已出方案”“已通过部分检查”写成全部可用。

### 同一目标与进展的写法示例

以下是写法演示，不代表当前项目事实。

**目标：** 让不同 Agent 能够接手同一个项目，继续维护共享进度。

**当前进展：**

> Codex 已能打开指定项目，读取概览和任务，并保存更新；保存后的内容已通过重新读取核对。Claude Code 的连接配置已准备好，但还没有在另一个真实会话中验证读取与更新，因此目前不能认为两个 Agent 的接手都已通过。
>
> 当前重点是完成 Claude Code 接手检查，再核对网页能否显示双方更新后的同一份进展。除此之外，两个 Agent 同时修改同一条记录时的冲突处理仍待检查。下一步先在 Claude Code 中打开同一个项目，完成一次真实读取和更新。

“正在完善多 Agent 协作”不足以作为进展，因为无法看出已有结果、未完成范围和下一步。目标也不应膨胀成上述工作汇报。

## 阶段进展

关键成果是有独立意义、值得后续回顾的结果。例如“两个 Agent 已能接手同一个项目”。过程中修改配置、修正措辞、运行检查等工作并入相关成果，不各写一条阶段汇报。

每条阶段记录包含成果标题、实际完成日期和比标题更详细的说明。说明写清已经达成的结果及适用范围；后续安排和剩余工作主要留在当前进展或任务中。已有同一成果时补充或修正原记录，不能因为另一位 Agent 再次接手就重复创建。

阶段进展默认折叠、最新在前。记录多时按需加载历史，不能一次展开所有历史使概览继续膨胀。当前简报修改的每个旧版本由现有变更记录保留，不自动变成阶段成果。

## 目标的完成与调整

- 可依据实际结果明确判断的目标，由 Agent 主动标为完成并归档；只有计划、代码或局部验证时不得提前归档。
- 需要用户主观认可的目标，先在当前聊天中具体询问，用户确认后再归档。不增加待决定页面、任务负责人或验收表。
- 改变方向、替换或不再推进的目标保留原文及调整日期，不冒充已完成。
- 归档后仍能展开查看原目标及日期。目标与阶段成果可以关联，已有相同成果时复用，避免两份相互矛盾的说明。

完成日期与保存时间分开表达。软件自动记录保存时间；正常完成时可以记录当时的完成日期。补录过去的成果时，仅在实际日期有依据或用户确认时填写，未知时保留未知，不能把导入时间或某次修改时间猜成完成时间。

## 概览页排布

```text
简介
项目用途与主要使用方式。

当前进展                           更新于……
较目标更详细的最新简报。
写明现状、已有结果、未完成范围及下一步。

▸ 阶段进展
  展开后按完成时间最新在前：
  完成日期  关键成果标题
            成果及范围说明

目标
仍在推进的一句话目标……

▸ 已完成目标
  完成日期  原目标内容……

▸ 已调整的目标
  调整日期  原目标内容……

功能与用法
当前能力及具体使用步骤。
```

用户与 Agent 面对同一份保存结果。归档区有记录才显示相应入口，默认不展示空卡片和长说明。最新进展保持完整正文阅读，不把它压成截断的一行。

## 软件与 Skill 的分工

软件需保存可独立识别的目标和阶段成果、状态与日期，提供真实的读写和归档工具，并在网页呈现折叠历史。更新沿用版本检查、客户端授权和自动变更记录，重复请求与不同 Agent 的接手不能产生重复归档或丢失他人修改。

Skill 要求 Agent：先读最新项目状态，重写当前简报，按实际结果判断是否达到关键成果或目标，再调用实际提供的工具保存。写入后重新读取核对。目标归档与阶段记录尚未提供工具时，明确说明未归档，不自造工具或绕过服务手改记忆库。

安装源 Skill 与内容标准按实际工具维护，并随实现同步本目录版本与两端安装文件。运行中的旧会话需要重新连接MCP获取新增工具。

## 后续实施的验收效果

1. 连续更新当前进展后，正文仍只有一份最新简报；保留必要背景与未验证范围，不因追求简短丢掉关键信息。
2. 普通聊天和保存不产生阶段记录；关键成果完成后出现一条，重复提交或另一 Agent 接手不增加重复项。
3. 目标完成后从当前列表进入折叠历史，展开看到原目标和真实完成日期；方向调整的目标明确区别于完成。
4. 主观目标未经用户确认不归档；用户在聊天中确认后，Agent 可完成保存，网页与工具读取一致。
5. 旧目标正文和旧进展迁移时原文可找回，不从历史文本猜测已完成目标、关键成果或完成日期。
6. 真实保存文件、工具返回、网页读取和自动变更记录一致；版本冲突与撤权规则仍生效。

具体数据格式、迁移、工具契约与验收进度见 [DYNAMIC-IMPLEMENTATION.md](DYNAMIC-IMPLEMENTATION.md)。
