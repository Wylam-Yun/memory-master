# 概览可读性审查与分层建议

日期：2026-11-05。状态：用户已确认保留完整简介作为项目打开后的默认内容，进展与目标单独成页；四个概览子页已实施并提供本机预览，等待用户查看阅读感受。用户本轮要求从人的阅读角度判断信息优先级、折叠与详情入口；审查后的实施见[四页实施计划](OVERVIEW-PAGES-IMPLEMENTATION.md)。

## 实际核对范围

通过本机Codex所配置的MCP打开memmaster，读取概览、任务、近期历史、活动/归档目标和阶段成果。核对OverviewPage、GoalProgress、AppShell、TasksPage、ResourceViewPage和HistoryPage的实现。将真实概览组件连接6421服务，在DOM中核对默认呈现与折叠状态；未使用computer use，没有浏览器截图或像素布局结论。

实际内容：简介241字符；当前进展604字符、4段；功能与用法1361字符、8项；项目约定515字符。现有4条活动目标、1条已完成目标、2条阶段成果。DOM默认可见文字约2345字符，8项功能全部常显。计数包含标点及正文格式字符，表示信息规模，不是阅读时间或屏幕高度测量。

## 主要问题

1. 简介、进展、目标和用法承担不同阅读任务，却全部连续展示。用户已明确认可现有简介的完整程度，并选择打开项目先看完整简介；需要通过独立页面访问进展与目标，不再通过压缩简介解决拥挤。
2. 当前进展混合用户可见结果、提交号、测试数量、来源许可、工作分支、未验证范围和下一步。下一步出现在第三段，正文无独立视觉定位。此前由Agent维护的内容本身也增加了阅读负担，前端重排与内容标准需要一起调整。
3. 功能与用法全文常显，比当前进展更长。新增功能会持续延长概览，项目架构链接还放在这段正文之后。
4. 四个原始正文区块使用相同标题层级和近似排布，未体现现状、目标、背景和操作说明的阅读优先级。
5. 阶段进展整体默认折叠是合理的，但展开后会显示整页记录的完整长正文；多条成果时再次形成长文。应先列成果标题、实际日期及一句结果，单条按需展开。
6. 目标中的完成、调整操作每行常显，阅读态和管理态混在一起。活动目标也没有明确的当前阶段重点；macOS等后续目标与近期目标同级。不能用数组顺序猜用户当前重点。
7. 编辑操作一次展开简介、约定、进展和用法四份长文本，修改一个内容也需要面对整份表单。后续应支持从对应区块进入单项编辑，保留版本核对与草稿。
8. 新增项目约定解决了长期决定的保存，但完整约定默认折叠不能保证当前关键限制被人看到。影响下一步的重要限制、阻碍、未验证状态必须在进展页直接可读。

任务页的已完成任务折叠、资料单独阅读页、变更记录按条展开可以保留。任务状态目前直接展示项目配置的英文值，普通用户阅读时还应核对显示名称；此项属于后续全页审查，不在本轮概览重排里顺手扩大范围。

## 用户确认的方向

- 保留目前简介的完整程度，不缩成一句话，不以行数或字数截断。
- 打开项目先看到完整简介。
- 当前进展与目标放在独立的“进展与目标”页。
- 之前的“摘要首页、简介放详情”建议撤回，不能继续作为实施依据。

## 已确认的导航与页面方案

保留现有五个一级入口，在概览内部提供四个独立页面。点击导航切换内容与地址，当前页只渲染对应正文，不是展开同一个长页面。这样“项目简介”“功能与用法”和“项目约定”都有足够阅读空间。

```text
左侧一级导航        概览内的页面导航
概览（选中）        项目简介 | 进展与目标 | 功能与用法 | 项目约定
任务
项目架构            项目简介                              编辑
资料                [保留现有两段完整简介]
变更记录            [本页专注阅读项目用途与背景]
```

默认选择“项目简介”。“进展与目标”入口常显，用户想看当前情况时一步进入。窄屏导航换行或变成明确菜单，不通过挤小字体适应宽度。各页使用相同字号与内容宽度，正文自然滚动，避免嵌套滚动框。

| 页面 | 正文与展示规则 |
| --- | --- |
| 项目简介 | 全文常显，保留现有完整自然段和正常字号；编辑只改简介。 |
| 进展与目标 | 最新详细简报与正在推进的目标为两个主要区块；简报说清结果、当前缺口和下一步，关键限制常显。阶段成果与目标归档从明确入口进入，默认不堆叠全文。 |
| 功能与用法 | 单独阅读当前能力与使用步骤；长内容可提供功能目录，用户点击定位或展开相应步骤，不占据简介与进展页。 |
| 项目约定 | 单独完整阅读已确认的决定、约束和必要排除项；影响当前工作的事项在进展页同时解释其影响。 |

阶段成果先显示标题、实际日期和一句结果，单条展开详情，再分页加载。已完成与已调整目标保留原文、日期，按需回顾。具体历史子路由与管理操作放在后续实施方案中确定，不擅自恢复待决定页面或复杂任务表单。

## 内容与工具需要配合的地方

本轮决定取消简介摘要与首页进展摘要的前提。简介全文和最新详细简报各在自己的页面阅读，沿用同一份正文，当前不需要为首页另维护一份摘要。

进展依旧比一句话目标详细、精准，用自然语言区分已完成结果、当前停点、未完成或未验证范围和一个下一步；补充说明有实际需要才按需展开。不能截取前100字或前三行冒充完整当前情况。是否需要调整保存结构，应在分页面需求确定后评估，不提前增加重复字段。

当前目标的重点来自明确用户意图，现有数据没有重点标识时先保留所有活动目标，不自动挑前三条，也不把后续目标删除或标为已调整。操作者与更新时间从实际保存记录取得，不推断Agent在线或正在工作。

## 阅读验收建议

- 打开项目默认看完整简介，原有自然段可正常阅读，不经过摘要截断或折叠。
- 一次点击进入进展与目标，离开简介后只显示该页内容。
- 进展页能直接知道实际结果、未完成或未验证范围、下一步及正在推进的目标。
- 用法与约定都有独立阅读位置，不因全文增长延长其他页面。
- 编辑只面对本页内容；草稿、版本冲突与保存后核对仍保留。
- 50条阶段记录不一次展开50份正文，逐条阅读和分页都保留日期。
- 宽窄屏及200%缩放以实际浏览器终态核对；本轮DOM审查不能替代该验收。

## 设计依据

[GOV.UK Details组件](https://design-system.service.gov.uk/components/details/)建议折叠只服务部分用户所需的次要内容，避免隐藏大部分用户必需的信息。[NN/g渐进呈现](https://www.nngroup.com/articles/progressive-disclosure/)说明先呈现重要内容，再以明确入口访问较低频细节。本项目按用户最新选择将不同阅读任务分到独立页面；在进展页保留关键现状与下一步常显，历史逐条阅读。简介保持完整，不套用摘要首页。
