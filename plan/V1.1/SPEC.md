## 目标与交付边界

Memory Master 面向普通用户，让人和多个 Agent 共同管理项目、共享进度和交接工作。活动筹备、内容创作、学习计划、调研、产品开发等项目使用同一套基本能力。简介讲清项目用途，目标表达用户可见效果，功能与用法说明当前可用的能力或交付内容及如何使用，进展表达当前现状。任务分 P0、P1，网页只展示 P0 任务。项目架构页帮助理解主要组成、工作流程和分工关系。页面按内容分页，日常阅读可以完整看到段落。

本次交付为 `plan/V1.1` 下的方案、内容标准、架构格式和 Skill 设计草案。产品实施在用户审阅后按下面的阶段推进。macOS 应用的既有发布目标使用这套本地网页和服务，DMG 发布前重复改造后的完整验收。

沿用已确认的 Markdown 项目存储。普通用户创建项目只需名称，概览等内容可与 Agent 逐步补齐。所有项目共用基本能力，不要求选择项目类型、提供源码或工作目录，也不引入各类型独立的流程。旧项目已有类型和目录信息保留，基本能力不依赖这些字段。

工作目录为可选关联，与记忆库目录独立。仅在任务需要读取本地文件时请用户指定相应位置。项目归属按用户明确指定的名称、ID 或已绑定目录解析，Agent 不凭当前目录猜测；临时杂事不写入项目。无工作目录的项目正常使用全部通用能力。

## 内容标准与 Skill 分工

协作 Skill 草案为 [COLLABORATION-SKILL.md](COLLABORATION-SKILL.md)，逐板块的自然语言写作标准与例子见 [CONTENT-STANDARD.md](CONTENT-STANDARD.md)，项目架构格式为 [ARCHITECTURE-FORMAT.md](ARCHITECTURE-FORMAT.md)。Skill 明确要求写入前读共同规则与对应板块标准，R3将同一份内容安装给两端。用户通过聊天协作，无需理解或选择 Skill、MCP、Git 或 Mermaid。

- `memory-master` 负责按名接手、功能与用法、项目架构、任务优先级与进展、用户提问、版本冲突和工作结束时的维护检查。
- [ARCHITECTURE-SKILL.md](ARCHITECTURE-SKILL.md) 保留为软件架构图的专项扩展草案，仅在用户明确需要该能力时适用。通用项目管理不以该扩展、源码调查或本地目录为前置条件。
- 简介和目标随用户确认的定位和范围变化更新。能力或交付内容验证可用后补入功能与用法，入口和操作步骤变化时同步更新。任务在关键节点更新，优先级随与用户确认的当前重点调整。整体状态变化时更新当前进展。主要组成、分工或流程变化时更新项目架构。
- 图和说明以用户确认的信息、选入的资料和实际工作结果为依据，区分当前事实与计划。缺信息时仅询问本次工作所需的内容，通用结构图无需源码或本地目录。
- 成功写入继续由系统自动留痕。普通更新直接提交字段，模型完成反馈无需额外填写系统已能生成的变更说明。
- Agent 需要用户拍板时直接在当前 Codex 或 Claude Code 对话里询问，得到答案后维护相关概览或任务。网页不新增问题页面、任务内问题标签或未回答数量角标；现有问题数据和接口保持兼容，不因移除页面规划而删除记录。

### Agent内容写作的交付要求

所有项目、概览、任务、资料、项目架构、变更记录和设置均在内容标准中说明来源、维护责任、具体写法和更新时机。概览进一步拆为简介、当前进展、目标、功能与用法。标准面向第一次接触项目的普通用户：使用完整自然语言、解释必要术语、交代对象和操作结果，不依赖聊天中的省略指代，不以比喻或技术关键词堆叠替代解释。

项目名称来自用户确认；文件原件来自用户选入；变更历史和配置状态来自系统，Agent不得为了填满页面编写这些数据。正文中区分当前事实、尚未验证的工作与未来目标。新增功能说明必须写明真实入口、操作步骤及可见结果。任务仍是名称和状态，写作标准不成为增加验收项或负责人字段的理由。

安装源与本机Codex、Claude Code的Skill及协作指令已同步动态概览规则。新增工具需由已开启会话重新连接MCP获取；安装与工具可用不等于真实LLM主动维护行为已验收。

## 网页信息结构

| 页面与路由 | 内容与交互 |
| --- | --- |
| 项目概览 `/projects/:id` | 按简介、当前进展、目标、项目功能与用法排列，以正文和标题呈现。每项可用能力或交付内容紧接使用方法，例如活动报名方式、调研报告的阅读方法。页面右上角提供「编辑」，进入编辑后显示简介、当前进展、功能与用法三个可增高字段；目标独立新增、完成与调整，归档和阶段成果默认折叠，具体行为见动态概览方案。 |
| 任务 `/projects/:id/tasks` | 只展示 P0 任务，主体是任务名称与状态，可直接勾选整条任务完成。已有说明按需展开，不提供验收清单、负责人、任务内问题标签或 P1 切换入口。 |
| 项目架构 `/projects/:id/architecture` | 项目的主要组成、工作流程或分工关系，用图和文字说明。名称与职责默认可读，点击节点定位相应说明；可选的资料来源和关联任务按需展开，图支持放大查看。无需源码或工作目录，也可先不建立结构图。 |
| 资料 `/projects/:id/resources` | 上传后点击文件名即可在网页查看内容；不新增单独的资料入口或让用户配置读取权限。不适合网页预览的格式提供下载。当前只列文件名，实施时补齐已有资料页的点击查看能力。 |
| 变更记录 `/projects/:id/history` | 按时间查看，支持已有时间范围查询。默认只呈现对象和变化摘要，长内容按条目展开前后值。 |

### 全局布局与文字

- 窗口宽度至少1200px时，侧栏224px、主区两侧内边距40px；960–1199px时分别为200px和32px。主内容内部最大1160px，概览正文最大820px，架构图使用主区完整宽度。
- 宽度640–959px时导航收进顶部「项目导航」菜单，主区两侧留24px；不足640px时留16px。顶部始终可辨认当前项目和页面，不把五个标签挤成小字号横向导航。
- 正文16px/28px行高，页面标题28px/36px（窄屏24px/32px），段落标题20px/28px，导航15px/24px，必要日期和文件大小14px/22px。技术路径等仅在详情使用13px等宽字。正文和编辑字段随内容展开，以页面滚动为主。
- 页面文案限于实际项目内容、控件标签和影响操作的状态。项目名在导航显示一次。日期、版本和路径在相关详情中出现，按用户任务提供必要信息。
- 项目概览统一按简介、当前进展、目标、项目功能与用法顺序排成一份文档。先认清项目再看最新进度，随后阅读目标和使用说明。可用能力或交付内容与用法逐项配对，尚无可用内容时如实留空。任务、项目架构、资料和历史在对应页面里呈现。
- 项目目录和客户端配置属于项目信息及应用设置，通过单独入口展开。

### 每页操作与状态

| 页面 | 主要操作 | 空内容和失败时的表现 |
| --- | --- | --- |
| 概览 | 编辑、保存、取消。编辑草稿在切换页面时保留，保存成功后切回正文。 | 简介、目标、功能与用法、进展缺失时，在对应标题下显示「未填写」和编辑入口。保存失败保留输入，版本冲突提供最新内容供比较。 |
| 任务 | 新建、改任务名称、更新状态或勾选整条任务完成；已有说明可展开阅读。 | 没有 P0 时显示「暂无 P0 任务」与新增入口。修改失败保留输入，勾选失败恢复到服务器状态并显示重试。勾选表示完成整条任务，不再要求逐项验收或填写负责人。 |

| 变更记录 | 按时间浏览，展开单条前后变化。 | 空列表显示「暂无变更」。长内容在展开的记录里完整阅读。读取失败显示重试入口。 |

五页共享项目 ID 和导航，具有各自可直接打开的路由。切换页面时保留编辑草稿及当前展开的任务说明。架构职责默认可读，节点定位短暂突出，不保留展开节点状态。服务断开、权限被拒和版本冲突提供对应操作所需的明确反馈。

### 示例二：任务列表与勾选

准备四条测试任务：TASK-1为P0待开始「补齐网页中的资料查看」；TASK-2为P0进行中「整理概览阅读排布」；TASK-3为P0已完成「确认五个页面的内容」；TASK-4为P1待开始「调整后续样式细节」。名称和状态由记录读取，界面只出现前三条，TASK-4始终不显示。

```text
任务                                         [＋ 添加任务]
P0 · 当前重点

☐ 整理概览阅读排布                         [进行中 ▾]
☐ 补齐网页中的资料查看                     [待开始 ▾]

已完成（1）                                    展开
```

- 添加任务只需名称，创建成功加入当前P0列表。已有描述点名称后在原行下方展开，空描述不显示占位段落。
- 勾选「补齐网页中的资料查看」后，整条任务变成已完成，进入折叠的已完成组，数量从1变2；展开后能看到已勾选的该任务。刷新和Agent读取同一条记录都应是已完成。
- 不显示完成百分比、子验收清单、负责人、目标编号等字段。主行只放勾选框、名称与状态，任务ID不占主要阅读位置。
- 状态下拉允许明确选择待开始、进行中或完成，实际选项及完成状态映射以项目配置为准。勾选后可通过状态选项改回未完成，不依赖自动猜测上一次状态。
- 写入失败恢复保存前状态，并在该任务附近提示重试；不能只改变浏览器里的勾选外观。

### 示例三：资料列表与点开后的内容

测试资料为UTF-8文件「需求说明.md」，原文包含标题「网页阅读要求」和一句「上传后点击文件名，即可在网页查看内容。」；另有一个不支持预览的二进制文件「参考附件.bin」。两份文件均仅是隔离验收样例。

```text
资料                                         [上传资料]
每份最多10MB

文件名称                            大小       更新时间
需求说明.md                         实际大小   今天       →
参考附件.bin                        实际大小   今天       →
```

点「需求说明.md」后，同一项目的主内容区进入阅读态：

```text
← 返回资料          需求说明.md               下载原件

网页阅读要求

上传后点击文件名，即可在网页查看内容。
```

1. 文件名本身就是可点击链接；不要求先选中、找另一个菜单或开启权限。侧栏仍在，当前页仍属于资料。
2. Markdown显示标题和正文，普通文本保留换行。内容来自实际上传文件，不从文件名生成摘要或填入演示正文。
3. 返回资料恢复原列表位置。下载原件保留原文件名与原字节；刷新阅读地址后仍能打开正确文件。
4. 「参考附件.bin」点开后显示文件名、大小、「此格式暂不支持网页预览」和下载按钮，不能显示空白页或把下载提示当成已预览。
5. 读取中仅阅读区显示加载状态；失败显示「读取失败」和重试。文件已不存在时显示「文件不存在」及返回资料，不能自动打开另一份文件。
6. 上传同名文件时，先提示替换或取消。替换成功后下一次打开显示新内容，取消则保留原文件；不承诺尚未实现的历史版本恢复。

### 示例四：项目架构与节点说明

```text

        [项目概览] ─说明目标→ [当前任务]
                                  │
                              更新进展
                                  ↓
        [项目资料] ─提供背景→ [项目记录] ─留痕→ [变更记录]

项目记录
维护当前状态，让人和Agent读取同一份内容。
```

图只表达该示例的项目管理关系，不把通用产品限定成代码工程。整体说明、关系图、各部分职责、主要流程依次排布。组成表在原位置转为一份说明列表，不同时显示原表和重复列表；名称与职责默认可读，点击节点滚动定位并短暂突出相应说明。来源及P0关联任务在「补充信息」中按需展开，空白项不占位。测试过程、接手状态和发布待办放在当前进展或任务。编辑预览与阅读共用布局。放大只放大图，不同时缩小字号或挤出一条窄右栏。没有架构内容时展示「尚未整理项目架构」，其余四页照常使用，不要求提供代码目录。

### 示例五：变更记录与前后值

### 按示例交付时的核对顺序

先用隔离项目建立上述四条任务、两份资料和概览内容，再逐页打开，分别核对：只显示当前页；P1不出现；勾选后的状态实际保存；文件点开内容正确；返回和刷新保留正确项目；图节点可选；历史摘要可展开。最后在1440px、1024px、640px和390px重复主要操作。本文示例不替代下方各阶段完整验收，也不能用纯前端演示数据充当接口接通。

## 数据与工具约定

### 项目架构记录

每项目按需新增 `memaster/architecture.md`，整体作为一个版本化记录。文件名及下列 API、工具名沿用内部标识，网页统一称「项目架构」，内容适用于任意用途的项目。格式见 [ARCHITECTURE-FORMAT.md](ARCHITECTURE-FORMAT.md)。组成表包含稳定 ID、名称和说明，可选的「关联任务」列填写本项目已存在的任务 ID。网页据此派生关联入口；任务可独立存在。

图源、组成说明和核对信息一起保存。来源可以是用户确认、项目资料或实际工作结果，源码位置仅是专项用途下的可选来源。读取返回完整 Markdown 和内容版本。首次创建使用空内容版本，已有记录使用最后读取的版本，格式同当前概览的内容哈希机制。

拟新增 API 与 MCP，以下为实施契约

```text
GET /api/projects/:id/architecture
GET /api/agent/projects/:id/architecture
返回 { content: string, version: string }

PUT /api/projects/:id/architecture
PUT /api/agent/projects/:id/architecture
提交 { content: string, baseVersion: string }
返回 { content: string, version: string }

architecture_read()
architecture_write({ content, base_version })
```

结构工具处理本会话已选项目。网页和 Agent 走同一个项目写入单元，执行授权、停服状态、版本检查、记录写入、历史追加和失败恢复。历史对象类型增加 `architecture`，网页显示「项目架构」。空结构读取返回空内容与空内容的版本，用户可在聊天中让 Agent 根据项目说明和资料整理，也可暂时留空。

Markdown 通过应用的受控渲染器展示，Mermaid 依赖本地打包并使用严格安全配置。组成表和图节点的关联由 Markdown 解析得到，脚本和可执行链接不进入预览执行流程。校验失败保留用户草稿并指出具体位置。

### 概览功能与用法

在现有概览的简介、目标、当前进展之外增加 `features: string`，承载可用能力或交付内容及逐项配对的使用说明，适用于任意项目，存入现有概览 Markdown。网页、项目服务、API 和 MCP 同步扩展读取与更新契约。旧概览缺少该字段时返回空字符串；只读取不改写磁盘，更新时保留其他原有内容。功能说明与其他概览字段共用版本、权限和自动历史机制。

### 简单任务与优先级

复用已有任务优先级字段，面向用户标为 P0、P1，内部沿用现有优先级规范化规则。项目任务 API、MCP 的创建、读取和更新均传递优先级。P0 表示当前重点，P1 表示后续安排。新增任务默认 P0，Agent 可明确创建 P1；旧任务未填优先级时按 P0 展示，读取不触发记录重写。保留旧任务已有的其他字段和优先级原值，禁止迁移时静默覆盖。

网页任务列表和关联任务入口统一只展示 P0。Agent 仍能读取、规划和维护两类任务；优先级调整走同一版本检查和历史写入流程。P1 保存在项目中，网页过滤属于展示规则。需要用户决策时在聊天中主动询问。变更记录保留完整历史供复盘。

任务面向用户只保留名称和状态，说明沿用已有可选描述，按需展开。勾选直接更新整条任务为项目配置中的完成状态；需要重新推进时可改回未完成状态。库 API 与 MCP 只补接必要的优先级字段，不为本版新增验收项、负责人或完成条件清单。旧记录已有其他字段原样保留，简化界面不能导致数据丢失。

### 网页内查看资料

用户在现有资料页点文件名即可看内容，这是同一页面流程内的阅读操作，不是增加一级菜单。当前 web API 只有上传和列表，Agent 有单文件读取能力；实施时在 web 授权下补齐单文件读取与下载，浏览器无需借用 Agent 凭据。先支持文本和 Markdown，其他格式提供下载，保留10MB限制及同名替换提示。

任务页的相关组成从结构表读取。Agent 更新项目架构时核对关联任务存在，移除组成时处理关联提示。结构可以关联任意优先级的任务，网页仅呈现其中的 P0 入口；没有结构记录时任务照常读写和完成。
