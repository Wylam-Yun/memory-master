# Memory Master 统一视觉与交互规范

状态：2026-11-05 设计建议，待高保真稿与真实页面验证。本文件参数是 Memory Master 的建议值，不是从参考站抓取的设计tokens，也不代表已实施。

目标：Modern / Minimal / Premium / Clean / Functional。品质来自内容层级、比例、对齐和稳定反馈。整个产品共用一套框架和组件，不为任务、资料和设置各做一种风格。

## 1. 空间与布局

| 项目 | 建议值 | 应用规则 |
| --- | --- | --- |
| 项目侧栏 | 宽屏224px，960–1199px时200px | 显示图标＋文字；不用永久图标窄轨替代可识别导航 |
| 主区宽度 | 内部最大1160px | 实际宽度=min(1160px,窗口宽−侧栏宽−两侧内边距) |
| 阅读正文 | 最大820px，常见760–820px | 中文约45–50字/行，随屏幕重排；概览和资料正文不为了铺满屏幕拉成长行 |
| 内容外边距 | ≥1200px：40px；960–1199px：32px；640–959px：24px；<640px：16px | 以实际窗口宽度为准，包括桌面软件窄窗口 |
| 主区页头 | 最小64px，内容可增高 | 标题左对齐、当前页主操作右对齐；窄屏操作移下一行 |
| 栅格 | 主区12列，列间24px | 用于必要的图/详情布局；普通文档仍是一列，无需每段占卡片 |
| 间距体系 | 4、8、12、16、24、32、40、48、64px | 控件内8–12，组内12–16，区块24–32，大段32–40 |
| 列表行高 | 任务最小56px，项目最小64px，资料最小56px | 长标题允许增高，禁止固定高度截掉含义 |
| 简短表单弹窗 | 480–560px宽，24px内边距 | 新建项目/任务用；不装长项目概览 |
| 图区 | 使用主区宽度，无固定视口高度 | 总图先保证可读，复杂图放大/细图，不能全图等比缩成小字 |

所有区块共享同一左对齐线。页头、正文、列表的边线不来回漂移。单页的阅读内容可以窄于任务列表，这来自阅读长度和扫描需求，侧栏、标题和控件语言仍然统一。

### 滚动规则

- 概览与编辑器随内容展开，以页面纵向滚动为主，禁止两行编辑框承载长说明。
- 项目导航可独立滚动以适应短窗口；正文中不继续套固定高度滚动卡片。
- 资料阅读和历史详情进入后保留返回位置；同一内容内部不再嵌套滚动正文。任务说明仅在列表内展开，不设计双栏任务工作台。
- 结构图是允许二维移动的特殊画布；文字说明、按钮与列表均正常重排。

## 2. 字体和文字层级

优先系统字体栈：macOS系统字体与苹方，其他平台使用系统无衬线与可用中文字体。首版无需加载外部字体，不复制参考案例中的商业字体。

| 用途 | 大小/行高 | 字重 | 规则 |
| --- | --- | --- | --- |
| 页面标题 | 28/36px，窄屏24/32px | 600 | 页面只有一个主标题 |
| 正文分区标题 | 20/28px | 600 | 简介、进展、目标、功能等同级 |
| 任务标题/列表主信息 | 16/24px | 500 | 长标题换行，不能缩成小灰字 |
| 正文、输入 | 16/28px | 400 | 正文对比度明确，输入时不缩字号 |
| 导航、按钮 | 15/24px | 500 | 文案短且可识别 |
| 必要元信息 | 14/22px | 400 | 时间、大小、提出者；不承载主要问题正文 |
| 技术细节 | 13/20px，等宽 | 400 | 路径、错误码、版本，仅二级详情使用 |

正文段落间12–16px，分区间32–40px，标题与正文间12px。主要内容不用全大写、超宽字距或装饰斜体。项目路径可换行或用明确查看操作，不让超长路径撑破页面。

压缩页面时先移走低频信息、调整布局和减少重复，再考虑密度；不通过把所有文字调成12px换取表面整齐。

## 3. 配色、表面和层次

首轮建议浅色系统，克制的蓝紫强调色。深色并非高级感的必要条件，若后续支持必须逐项适配，不直接反转颜色。

| 语义 | 建议颜色 | 使用范围 |
| --- | --- | --- |
| 画布 | `#FAFAF8` | 应用背景，接近中性色 |
| 内容表面 | `#FFFFFF` | 阅读主体、菜单、弹窗 |
| 主文字 | `#202124` | 标题、正文、任务名、文件名 |
| 次文字 | `#555B65` | 必要元信息；控制数量而非降低到难读 |
| 强调色 | `#3B57D0` | 主按钮、链接、选中状态、焦点 |
| 选中底色 | `#EEF2FF` | 侧栏当前页与当前列表项，搭配强调文字 |
| 装饰边线 | `#E5E7EB` | 必要列表分隔；不承担输入边界或焦点识别 |
| 输入边界 | `#8A9099` | 需要识别边界的表单控件 |
| 成功文字/底 | `#216C45` / `#EDF8F0` | 保存、配置成功等明确结果 |
| 待处理文字/底 | `#88550D` / `#FFF6E4` | 等待接入、需要注意 |
| 错误文字/底 | `#B42318` / `#FFF1F0` | 失败与冲突提示 |

状态色只用于状态，不给每个模块、Agent、项目分配一种品牌色。文字标签始终与颜色并存。普通信息不能只靠红绿区分。

普通正文按至少4.5:1、大字按相应条件至少3:1核对，依据 [W3C文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。浅色分割线只作辅助；交互组件与焦点还需要单独核对非文本对比度。

### 边框、圆角与阴影

- 页面正文不套卡片。任务和资料以行对齐，弱化或省去不必要的分隔线。
- 控件圆角8px；菜单、弹窗12px；状态标签6px。不在同一页面混用药丸按钮、方框按钮与超大圆角面板。
- 阴影只帮助浮层与背景分离，默认一个轻层级。普通列表、概览段落、图节点不重复使用漂浮阴影。
- 底色主要区分导航、内容和浮层，不使用满屏渐变、玻璃效果或重背景插画。

## 4. 图标和控件

建议统一用已有图标方案或一套打包的线性图标，视觉尺寸18–20px、线宽约1.75–2px。新增图标依赖须评估体积和许可，不从多个图库混搭。

| 控件 | 规则 |
| --- | --- |
| 导航 | 图标＋文字，当前页有浅底和明确文字变化；焦点与选中不同 |
| 主按钮 | 当前操作组一个强调按钮，高度40px；触屏有效目标44px |
| 次按钮 | 中性文字或轻边界，不与主按钮同强度 |
| 图标按钮 | 提供可见或可访问名称；主要操作不能只靠悬停发现 |
| 输入框 | 外置标签，placeholder只作例子；错误靠近字段，不用占位文字代替标签 |
| 多行正文 | 足够高、可增高；保留换行，编辑模式与阅读模式明确 |
| 复选框 | 整行标签可点；勾选直接代表整条任务已完成，不增加验收清单 |
| 状态选择 | 显示当前状态与合法选项，保存后反馈；不使用含糊「推进」 |
| 开关 | 只控制允许访问；旁边单独写配置与接入结果 |
| 标签 | 仅P0、任务状态、必要的失败/待处理状态；不把每个元字段都包成徽章 |

指针目标至少按 [W3C最小目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 的24×24px及例外规则核对；本项目触屏44×44px是额外设计目标，不误写成该AA条款的强制数值。

## 5. 页面跳转、详情和局部操作

1. **导航就是地址变化。** 项目页支持直接打开、刷新、后退，当前项目始终可辨认。点击对象不能仅改一块无地址状态而让分享和后退失效。
2. **说明按需出现。** 任务以名称加状态呈现，已有说明在列表内展开。资料阅读和历史详情按需进入，无常驻右栏。
3. **短动作使用弹窗。** 新建项目、简单新任务；Esc关闭、焦点回到触发按钮，有未保存内容时先处理草稿。
4. **长文就地编辑。** 概览在主区编辑，保持阅读宽度；不放窄抽屉、不新增全屏编辑器产品。
5. **元信息逐步展开。** ID、绝对路径、版本、原始错误和安装文件放到详情；任务只显示名称与状态，不增加验收项或负责人字段。

页面级焦点进入新标题，详情关闭恢复原选择。菜单支持键盘、Esc、焦点可见；导航提供跳过到正文。避免快捷键成为唯一操作入口，不占用中文输入法的正常行为。

## 6. 状态反馈与并发协作

| 事件 | 反馈 | 数据要求 |
| --- | --- | --- |
| 点击保存 | 按钮进入保存中，禁止重复提交 | 不在服务器确认前显示已保存 |
| 保存成功 | 对应区域短暂显示已保存 | 返回版本与重读结果一致 |
| 保存失败 | 字段旁说明失败与重试，保留输入 | 无成功提示、无假历史 |
| 版本冲突 | 提示另一方已更新；提供最新值与本地草稿比较 | 重新读取最新版本后明确决定如何保存 |
| 其他Agent更新 | 阅读态重新验证；编辑态显示有新内容 | 不能自动覆盖输入，不能假装实时共同编辑 |
| 上传 | 上传中→已完成或失败 | 没有真实进度数据就不显示百分比 |
| 启用客户端 | 配置中→等待接入→已接入 | 开关允许、安装成功、bridge接入三者区分 |
| 服务断开 | 一条全局提示＋重试，暂停写入 | 保留草稿，不把数据变为空态 |

已有接口可以支撑手动刷新与窗口聚焦重读；页面可见时可考虑约10–15秒的低频检查，实际间隔需性能验收后确定。离开页面停止检查，按项目和对象合并请求。当前不存在实时订阅、在线心跳、任务执行流，不用动画圆点制造这些假象。

概览草稿按项目ID隔离，任务草稿按项目与任务ID隔离；退出编辑或切页不应让其他项目获得这份草稿。持久化草稿如采用浏览器存储，须单独确定过期和清理规则，敏感访问密钥继续按现有边界处理；不能把密钥随草稿写到长期存储。

## 7. 动效

建议状态与按钮反馈120–160ms，菜单/详情展开160–220ms，优先轻透明度与小幅位移。数字是本项目参数建议，不是对参考站的测量。

- 任务勾选后就地反馈；成功不抖动整页、不插入大幅庆祝。
- 页面切换无需全屏遮挡过场，加载只影响对应内容。
- 尊重减少动态效果偏好，移除非必要位移；焦点和错误反馈仍然可见。
- 数据结果先确定再动画表现，动画不延迟授权撤回、保存结果或错误提示。

## 8. 响应式规则

| 实际窗口宽度 | 导航与内容 | 列表/详情与结构图 |
| --- | --- | --- |
| ≥1200px | 224px侧栏，主区40px边距 | 任务列表内展开说明；资料阅读用主区，图使用可用宽度 |
| 960–1199px | 200px侧栏，主区32px边距 | 不常驻右栏，任务列表内展开，概览保持16px正文 |
| 640–959px | 顶部当前项目＋「项目导航」菜单，24px边距 | 项目内容单列；任务状态可换到第二行，保留文字导航 |
| <640px | 顶部56px左右、16px边距，导航按需展开 | 详情全页；文件大小/日期移次行；差异上下展示；结构图可局部移动 |

收起导航时仍显示当前项目名和当前页名，导航菜单内明确选中项。无需一条横向滚动的小字号中文导航，也不因为手机尺寸增加与桌面不同的业务入口。

普通正文在320 CSS px宽度与放大时应重排，不丢信息或操作；二维图表可在自己的区域保留二维布局。依据 [W3C重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。长项目名、长文件名、200%缩放、短高度窗口均需单独检查。

## 9. 文案纪律

- 用「项目」「任务」「项目资料」「项目架构」「变更记录」「设置」等具体名称。
- 核心内容用正常字号与对比度。辅助文字只解释会影响操作的事情，如10MB、覆盖原件、需打开新会话。
- 不在每页重复「让人和Agent共同协作」「一切尽在掌握」等介绍。
- 未填写、未接通、配置失败、服务停止分别如实表达；不能把它们统一画成没有数据。
- 问题、答案与任务说明保留原意。摘要仅从真实结构字段派生，不增加自动改写或自动总结能力。

## 10. 高保真稿和实施验收清单

- 使用当前仓库的长内容及独立测试库，至少覆盖30条任务、30份资料、100条历史和长资料正文；不能只用三条短样例宣称完成。
- 所有页面共享颜色、字号、间距、按钮、输入、导航和错误组件；完整文案可读，无重复卡片嵌套。
- 320/390/768/1024/1440px及200%缩放逐页核对，普通正文不内滚动或横向溢出。
- 键盘可完成项目选择、展开任务说明、勾选完成、上传触发和设置；焦点返回合理，弹窗不困住焦点。
- 手工与自动检查对比度；状态不仅靠颜色，触屏目标不相互挤占。
- 每个可点击控件都有真实接口或明确的局部行为；未实现功能在设计与实施依赖中标注，不用空按钮交付。
- 保存/任务完成/上传后从网页、API及磁盘核对终态，并由真实客户端读取；断连、冲突、重试、撤权分别验收。
- 本清单是未来UI交付门槛。本轮只有文档和现状研究，不能标记为新产品功能已通过。
