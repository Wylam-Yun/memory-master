# Memory Master V1.0 产品规格

状态：待用户审阅  
日期：2026-11-04

## 1. 产品定义

Memory Master 是面向普通用户的本地项目管理与交接软件。同一台 Mac 上，用户通过网页管理项目，Codex 和 Claude Code 在各自原有的对话界面工作，并通过 MCP 读写同一份项目进度。多个 Agent 可以分别推进任务，也可以中途接手。用户需要判断时，Agent 主动在对话里提出问题，并把待决定事项留在项目里。

第一版的使用目标是让用户只交代要做的事。Agent 能找到正确的项目、读懂现状、在关键节点更新，并把需要人判断的事项带给用户。换一个 Agent 后，已提交的进度和决定可以直接接着用。

第一版先用本地网页试用，最终以 macOS DMG 交付。飞书同步、跨设备共同编辑和高级检索留给后续版本。

## 2. 记忆库、项目与工作目录

用户首次打开软件时确认一个记忆库位置。软件提供默认位置，也允许用户选择自己的文件夹。每个项目在记忆库下有一个独立目录，项目概览、任务、待决定事项、资料清单和变更记录以该目录下的结构化存储为权威来源（任务等内容沿用现有 Markdown 记录格式，项目配置与元信息保存为配置文件）。用户上传的原文件保存在同一个项目目录里。

```text
~/Documents/MemoryMaster/       用户选择的记忆库
  订单系统/
    memaster/                    项目结构化存储（权威来源）
      config.yml                 项目配置与元信息
      overview.md                项目概览
      tasks/  docs/  decisions/  任务、文档、决定等记录
    资料/                       用户上传的原文件
  旅行筹备/
    memaster/
    资料/

~/work/order-system/            订单系统可选关联的工作目录
```

- **项目概览**包含项目是什么、想达成什么效果、当前做到哪。用户和 Agent 共同维护。普通任务状态变化直接体现在任务列表里，项目整体状态或目标变化时再更新概览。
- **任务**记录正在做的事和当前状态。多个 Agent 可以分别更新不同任务，网页首页汇总当前进度。
- **资料**由用户主动上传，归到对应项目。默认记忆内容是项目管理信息。方案正文、测试数据、实现代码和具体细节在用户明确选入后才纳入记忆库。Agent 先看资料清单，按需读取指定文件。
- **变更记录**按项目保存，供用户回看一个时间段内谁改了什么。

关联工作目录是可选项。用户明确指定项目路径或名称后，服务根据项目清单解析为稳定的项目 ID。找不到或有歧义时，Agent 请用户确认。从无关目录启动也可以按名称接手。已选项目在对话中保持到用户明确切换，项目 ID 决定写入落到哪个项目目录。只有明确归属该项目的工作才记录。同一对话里临时交代的杂事也应跳过，归属不明确时暂缓写入。

现有 `memaster init` 会在当前目录下建立项目存储并可选配置 Agent。V1.0 将「新建项目」和「连接 Agent」做成两个独立的网页操作。用户可以先连接 Agent，之后再创建更多项目。现有网页和任务操作可以复用，项目状态的持久化由记忆库下各项目目录内的结构化存储管理（沿用现有 Markdown 存储格式）。

## 3. 应用生命周期与客户端权限

应用运行期间，本地网页和记忆库服务可用。关闭网页只收起界面，Agent 可以继续工作。退出 macOS 应用后，本地服务停止，已有 Agent 会话的读写请求也会失败，并收到可理解的提示。重新打开应用后恢复之前保存的授权状态。

网页设置提供 **Codex** 和 **Claude Code** 两个独立的「允许访问记忆库」开关。首次使用时默认关闭。权限以客户端为单位，允许访问整个记忆库。

- **首次开启**自动设置对应客户端的 MCP、用户级指令和协作 Skill。Codex 使用 `AGENTS.md`，Claude Code 使用 `CLAUDE.md`。软件保留用户已有内容，只管理自己的配置。连接探测确认客户端接通当前记忆库后，才开放项目读写并显示「已连接」。探测期间只开放验证连接所需的接口。如果需要重启客户端，界面说明原因和下一步。配置失败时保持拒绝访问，界面显示可重试状态。
- **关闭**由记忆库服务撤销该客户端的访问权限。关闭成功后，旧会话和新会话发起的项目列表、概览、任务、资料、待决定事项和历史读取，以及所有写入，都应被拒绝。另一个客户端和本地网页可继续工作。
- **重新开启**只恢复被选中的客户端。软件复用并检查之前安装的配置，修复缺失的自管配置，验证连接后恢复可用状态。撤销前的会话凭据不能用于绕过当前的授权状态。

每个客户端通过独立的访问凭据标识。服务端对每次受保护的调用检查当前授权，以服务端识别的客户端身份写入变更记录。停用和写入按明确的顺序生效，关闭操作返回成功后，已撤权客户端的写入不得继续提交。服务停止后，客户端也无法通过旧连接继续操作。

开关的强制范围是 **Memory Master 提供的访问**。Agent 通过其他工具直接访问用户文件时，读取权限由 macOS 决定。Agent 已经读到并留在对话里的内容由相应客户端管理。

## 4. 协作与变更记录

### Agent 工作方式

用户级短指令负责触发行为。用户提到继续或处理一个 Memory Master 项目时，Agent 先选定项目并读取概览、相关任务和待决定事项。在接手、遇到阻塞、解除阻塞和完成任务时主动更新进度。Skill 维护详细操作和示例，包括项目选择、冲突重读、提问和接手。MCP 提供实际的读写能力。用户可以在原有对话里直接说「继续订单系统的退款任务」。**阶段 3 编写短指令和 Skill，并在真实客户端验证。阶段 4 实现一键安装、重试和连接验证。**

常规执行由 Agent 自行处理。涉及用户预期结果的变化，或确实需要用户提供信息、权限或决定时，Agent 在当前对话提出具体问题，同时在项目中留下关联任务的待决定事项。用户可以在对话里回答，由 Agent 记录，也可以直接在网页回答。后续 Agent 能读取问题和答案，并按最新状态接手。

### 项目存储写入时机与自动留痕

| 操作 | 何时更新项目存储 |
| --- | --- |
| 创建项目 | 用户在网页确认创建时，初始化项目目录与结构化存储并写入初始项目资料。阶段 1 起生效。 |
| 编辑概览或任务 | 网页提交有效修改或 MCP 收到已授权的更新请求时立即写入。Agent 在接手、阻塞、解除阻塞和完成时，有实际进展变化就主动提交。阶段 1 起保存项目状态。 |
| 创建或回答待决定事项 | Agent 记录问题、用户在网页回答，或 Agent 记录用户在对话中的答案时立即写入。阶段 3 起生效。 |
| 上传资料 | 用户提交上传，原文件已保存到项目目录且可读取后，再提交资料清单和对应的变更记录。成功响应时文件和清单都可用。阶段 4 起生效。 |

写入在实际操作发生时提交，成功响应表示数据已经提交到对应项目的存储。打开项目、查看资料、普通聊天、项目外的杂事以及无实际变化的操作都不更新项目数据。选择记忆库位置、启停客户端和记录连接状态属于应用设置，独立于项目存储。

每次成功修改项目内容，系统自动记录时间、操作者、对象和改动前后的值。网页操作归为用户，Agent 操作按受验证的客户端身份记录。上传等文件操作记录资料名称和动作。普通进度更新只提交要变更的字段，用户和 Agent 无需另填原因、结果或证据链接。

从阶段 2 起，服务在同一个写入单元里核对记录版本、更新项目状态并追加变更记录（同一项目写锁保护下的原子提交）。提交完成后才返回成功。两方基于同一个旧版本修改同一条记录时，先提交的一方生效，另一方收到冲突和最新值，再决定是否重试。不同记录可以独立推进。失败、被拒绝和无实际变化的调用都不产生成功变更记录。

## 5. 开发阶段与验收

按下面顺序开发。前四个阶段都用本地网页与实际服务验收。第五阶段使用从 DMG 安装的应用重复关键场景。每个阶段都以表里的外部结果作为通过条件。调用成功或失败要核对外部返回状态，写入还要从独立读取入口或磁盘核对终态。涉及多个项目、任务或客户端时分别断言。每阶段交付用户可见变化时，同步更新对应的用户指南、README、架构说明和变更日志。

### 阶段 1 · 网页交接与权限底座

**交付**：开发环境可以启动本地网页服务，从页面选择记忆库、创建多个项目并编辑概览和任务。每个项目从本阶段起使用独立目录内的结构化存储保存项目状态。MCP 可从任意目录按名称打开项目。网页提供客户端授权开关，服务执行独立授权、即时撤权和退出停用。此阶段可用受控测试连接器预先配置两端，正式的一键配置在阶段 4 交付。

| 验收操作 | 预期结果 |
| --- | --- |
| 在网页选择一个独立的记忆库，创建「订单系统」和「旅行筹备」，前者可关联另一个工作目录。 | 记忆库下有两个独立目录，各有一个可以独立读取的项目存储（memaster/ 结构）。记忆数据写入各自的项目目录，无工作目录的项目照常可用。 |
| 从无关目录启动客户端，按名称打开「订单系统」，读取概览并更新任务。另一个会话打开「旅行筹备」。 | 独立读取两个项目的存储并核对网页，确认更新只落在「订单系统」。「旅行筹备」保持原值。两个会话各自保持已选项目，模糊名称要求明确选择。 |
| 启用两个客户端身份，分别验证读写成功。网页关闭其中一个开关，从该身份的旧会话和新会话发起读取、写入和列举项目请求。 | 被关闭端的每类操作都返回拒绝，磁盘状态保持关闭前的最后一次合法写入。另一端和网页继续读写。换另一端关闭，重复验收。 |
| 让客户端写入请求在提交前等待，同时关闭它的开关，再放行等待中的请求。 | 撤权返回成功后，等待中的写入无法落盘，网页能读到关闭时的最后一份状态。 |
| 关网页后尝试读取和更新，再停止本地应用服务后重试，最后重启。 | 关网页后读写仍成功。服务退出后两个客户端均无法读写。重启后按原授权状态恢复。 |

### 阶段 2 · 共享进度、并发写入与时间线

**交付**：在阶段 1 的项目存储上加入版本检查和变更记录。网页与 MCP 走共同的写入规则，状态更新和历史记录在同一个写入单元提交。后续阶段引入的待决定事项和资料沿用这套写入与历史规则。

| 验收操作 | 预期结果 |
| --- | --- |
| 两个独立 MCP 会话并行更新不同任务，再从网页编辑项目概览。 | 两条任务和概览分别从独立入口读到正确终态，磁盘内容与网页一致。时间线分别显示两次 Agent 更新和一次用户更新。 |
| 两端先读同一旧版本，再分别更改同一任务或概览。 | 一方成功，另一方得到明确的冲突结果和最新值。刷新后仍是成功写入的值，时间线只有一条成功变更。任务和概览分别验证。 |
| 让一次写入在更新状态后、写入历史前失败，再从网页和磁盘上的项目文件独立读取。 | 操作返回失败。项目状态和历史都保留在上一次成功提交时的值。 |
| 重启服务，再检查某段时间内的历史。 | 逐条找到对应时间、操作者、变更对象和前后值。更新时无需补填其他说明。 |

### 阶段 3 · 真实 Agent 主动协作

**交付**：编写用户级短指令和协作 Skill，用测试配置接入 Codex 与 Claude Code。补齐项目首页的待决定事项和对话、网页两条回答路径。使用真实客户端验证日常指令可以触发协作。

| 验收操作 | 预期结果 |
| --- | --- |
| 分别在真实 Codex 和 Claude Code 会话交代任务，其中一个从无关目录启动。只说要做的工作和必要的项目名称。 | 两个客户端各自主动读取项目并在接手、阻塞、解除阻塞和完成时更新。用户无需提醒先读或记进度。网页和时间线分别确认每个客户端的更新。 |
| 在两个真实会话中，各自在已接手项目后临时交代一件与项目无关的杂事。 | Agent 可以完成杂事。分别检查项目存储和时间线，确认杂事没有产生项目更新。 |
| 给 Agent 一个会改变用户预期结果的选择，例如是否允许二次部分退款。 | 它在当前对话提出具体问题，首页出现关联任务的待决定事项。一个已有授权范围内的常规执行选择可继续进行。 |
| 第一次在网页回答待决定事项，关闭原会话后新开另一个 Agent 接手。再用另一条待决定事项验证对话回答路径。 | 两次答案分别保存并可读取。接手的 Agent 能基于最新进度和决定继续。网页能看到事项已经处理，时间线记录对应变更。 |

### 阶段 4 · 完整网页试用与一键配置

**交付**：把保存位置、创建项目、连接状态、单独启停两个客户端和上传资料串成网页体验。首次开启任一客户端时，由软件自动设置 MCP、短指令和 Skill。

| 验收操作 | 预期结果 |
| --- | --- |
| 在已有 Codex 和 Claude Code、没有 Memory Master 配置的测试用户环境中，从网页分别开启两个客户端。 | 两端的配置都实际生效，各自能从真实客户端按名打开项目。用户原有配置保留。界面状态和验证结果逐个对应。全程通过网页完成 Memory Master 设置。 |
| 模拟一个客户端配置失败，再恢复条件并重试。关闭后重新开启，重复运行配置。 | 失败时显示原因和可重试状态，权限保持关闭。重试后实际连接成功。重复开启不产生重复配置，另一个客户端的状态保持可用。 |
| 在网页向两个项目分别上传不同资料，例如一份 Markdown 方案和一份 CSV 测试样例，用 Agent 分别按项目打开。 | 每个原文件保存到所属项目。逐份核对清单和读取结果，确认项目之间的资料没有混入。关闭该客户端开关后，旧会话的资料列表和读取请求均被拒绝。 |

### 阶段 5 · macOS DMG 发布验收

**交付**：使用同一套本地网页和服务，交付可从 Finder 打开的 macOS 应用。应用携带 Memory Master 所需运行组件，并以 Developer ID 签名和公证的 DMG 供用户下载。Mac 上的 Codex 和 Claude Code 由用户使用自己已有的安装和账户。

| 验收操作 | 预期结果 |
| --- | --- |
| 在所声明支持的干净 macOS 环境中，从下载的 DMG 安装，双击应用。 | 系统接受签名和公证。应用正常打开网页，无需安装 Bun、运行 `memaster init` 或手动写 MCP 配置。 |
| 从安装后的应用创建项目，开启两个客户端，完成一次真实交接。 | 任意目录启动的 Agent 能按名接手。网页能看到正确进度、待决定事项的答案和变更记录。 |
| 在已打开两个 Agent 会话时，依次关闭网页、关闭一个客户端开关、退出应用并重启。 | 关闭网页后读写照常。单独关闭开关后该端读写被拒绝，另一端可用。退出应用后两端均停止。重启后数据仍在，两个开关分别恢复原状态。 |

## 6. 首版完成标准

普通用户可以从 DMG 安装并打开应用，在网页建项目、上传资料、连接两个 Agent。随后只在 Codex 和 Claude Code 里交代工作，就能完成并行推进、用户拍板和跨会话接手。网页能查到每次实际发生的修改，单独关闭客户端或退出应用时，能看到相应的读写访问确实停止。
